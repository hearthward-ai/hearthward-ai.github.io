How the guard works

A closer look at Threshold, Knock and Gatehouse. This is the planned design; the guard is in development.

Home Threshold Knock Gatehouse Limits

The idea in one minute

An assistant that reads outside text (chat messages, email, attachments, web pages, tool output) can be tricked by instructions hidden in that text. This is called prompt injection. Hearthward does not try to make the model immune. Instead the guard sits around the model and does three jobs: it checks what goes in, it controls what the assistant is allowed to do, and it checks what goes out.

The picture is on the home page. The guard parts are meant to be a plug-in (an add-on) for Hermes Agent (Nous Research). Everything below is the design and the current state of the work, not a finished product.

Threshold: scan and fence what comes in

Threshold looks at untrusted text before the model sees it.

  • It applies rule-based checks for hidden characters, text that looks like instructions to the assistant, and common injection tricks.
  • Optionally, a small local model with no tools can take a second look. It can only judge text; it cannot act.
  • Text that looks suspicious is held for you (the person running it) instead of being passed on. You answer with a short reply, follow <id> (go ahead) or ignore <id> (drop it).
  • Text that passes is fenced off (clearly marked as “material to read”), and the model is told to treat it as material to read, not as orders. This part is best effort.
  • Pictures can be read with an OCR tool (Tesseract; it reads the words in a picture) and checked for common scam signs, in English and Chinese.

Knock: any action asks first

Knock is a policy on what the assistant may do, not on what it may say. Ordinary replies do not need your approval.

  • The model only writes text. Sending, changing and deleting are done by ordinary program code (not the AI), which waits for your yes.
  • A never-allowed list names actions that are refused outright.
  • A taint rule: once the assistant has read outside text, it counts as “contaminated” and may not act on its own. By design, a hidden instruction cannot trigger an action by itself.
  • Tool allowlists (a short list of what it may do) decide which actions can run at all, and which ones ask you first.

Gatehouse: check what goes out

Gatehouse is the last stop before a reply leaves.

  • Replies are filtered for secrets, hidden characters and links that could carry your data out.
  • By design, replies and emails go only to recipients you approved.
  • If the guard cannot confirm that it is active, the assistant is designed to stay offline rather than run unprotected (still being tested).

What the guard cannot do

The guard is best effort. Rules and a small local model catch many attacks and some scams, and miss others. Rewordings, new tricks and unusual file types can get past it. It lowers the risk of prompt injection and does not remove it. “No clear signs” is not a promise that something is safe, so check anything important yourself.

Asking first only helps if you read what you approve: a tricked assistant can still ask for something harmful, so check each request before you say yes.
